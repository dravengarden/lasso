# Feature recipe

Persist `brief.md` only when scope or acceptance must survive a handoff. Keep it
outcome-oriented; the live implementation plan belongs to Codex.

Use `assets/feature.md` and retain only:

- Observable outcome and users affected.
- Explicit non-goals that prevent scope drift.
- Constraints or compatibility boundaries.
- Acceptance evidence that cannot be inferred from the project's normal gate.

Avoid implementation checklists, stored progress, generic “tests pass” cases,
and details already enforced by `AGENTS.md` or project tooling.
