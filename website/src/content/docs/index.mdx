      <div class="section-kicker">01 / IN PLAIN ENGLISH</div>
      <h2 id="intro-title">A shared map for AI coding work.</h2>
      <p>Lasso gives every agent the same answer to three basic questions: which repositories exist, where should I work, and which rules and capabilities should I load?</p>
    </div>

    <div class="value-grid">
      <article class="value-card">
        <span class="card-number">01</span>
        <div class="card-icon" aria-hidden="true">REPO</div>
        <h3>Find every repository</h3>
        <p>Register independent repositories or true monorepo subdirectories in one small, readable catalog.</p>
        <code>project-defs/</code>
      </article>
      <article class="value-card value-card--featured">
        <span class="card-number">02</span>
        <div class="card-icon" aria-hidden="true">TASK</div>
        <h3>Work without collisions</h3>
        <p>Give each task its own Git worktree while stable checkouts remain clean integration inputs.</p>
        <code>worktrees/&lt;project&gt;/&lt;task&gt;</code>
      </article>
      <article class="value-card">
        <span class="card-number">03</span>
        <div class="card-icon" aria-hidden="true">EXT</div>
        <h3>Load the right capabilities</h3>
        <p>Share project rules, language conventions, skills, hooks, and checks across supported agent runtimes.</p>
        <code>plugins/ + modules/</code>
      </article>
    </div>
  </section>

  <section class="landing-workflow" id="how-it-works" aria-labelledby="workflow-title">
    <div class="section-heading section-heading--split">
      <div>
        <div class="section-kicker">02 / HOW IT WORKS</div>
        <h2 id="workflow-title">From repository list to isolated task in three steps.</h2>
      </div>
      <p>Lasso coordinates the workspace around your tools. Git still owns branches and worktrees. Each project still owns its build, test, and deploy commands.</p>
    </div>

    <ol class="workflow-list">
      <li>
        <div class="workflow-index">01</div>
        <div class="workflow-copy">
          <span>CREATE THE WORKSPACE</span>
          <h3>Choose your runtimes and starter modules.</h3>
          <p>This creates the shared contract, lock file, runtime adapters, and core plugin.</p>
        </div>
        <code>lasso init ~/my-workspace --runtime=codex,claude</code>
      </li>
      <li>
        <div class="workflow-index">02</div>
        <div class="workflow-copy">
          <span>REGISTER REPOSITORIES</span>
          <h3>Declare identity, then materialize stable checkouts.</h3>
          <p>The registry stores repository identity—not a second build system or deployment DSL.</p>
        </div>
        <code>lasso project add --project=app --repo-url=…</code>
      </li>
      <li>
        <div class="workflow-index">03</div>
        <div class="workflow-copy">
          <span>START A TASK</span>
          <h3>Create an isolated surface and let the agent execute.</h3>
          <p>The agent follows the nearest project guidance and uses the capabilities installed in the workspace.</p>
        </div>
        <code>lasso worktree create feature-login --project=app</code>
      </li>
    </ol>

    <div class="ownership-strip" role="note">
      <strong>Lasso coordinates.</strong>
      <span>Agent runtimes own goals and sessions.</span>
      <span>Git owns branches and worktrees.</span>
      <span>Projects own build, test, and deploy.</span>
      <a href="/lasso/concepts/core-mechanism/">Read the core mechanism <span aria-hidden="true">↗</span></a>
    </div>
  </section>

  <section class="landing-plugins" id="plugins" aria-labelledby="plugins-title">
    <div class="section-heading section-heading--split">
      <div>
        <div class="section-kicker">04 / PLUGIN ECOSYSTEM</div>
        <h2 id="plugins-title">Extend the workspace without forking the core.</h2>
      </div>
      <p>Lasso modules are versioned capability packs. Install only what your workspace needs; every installed version is recorded in <code>lasso.lock.toml</code>.</p>
    </div>

    <div class="plugin-kinds">
      <article>
        <span class="plugin-kind">CONVENTIONS</span>
        <h3>Teach agents your engineering language.</h3>
        <p>Shared guidance for Go, Rust, Nix, and repository-specific working rules.</p>
        <div class="module-tags"><code>lang-go</code><code>lang-rust</code><code>lang-nix</code></div>
      </article>
      <article>
        <span class="plugin-kind">CAPABILITIES</span>
        <h3>Add deterministic workspace checks.</h3>
        <p>Scripts and contracts that agents can run and CI can verify consistently.</p>
        <div class="module-tags"><code>docs-index</code></div>
      </article>
      <article class="plugin-card--featured">
        <span class="plugin-kind">PLUGINS</span>
        <h3>Give agents reusable workflows.</h3>
        <p>Skills, hooks, and runtime manifests for security, memory, and session safety.</p>
        <div class="module-tags"><code>security</code><code>hooks</code><code>memory</code></div>
      </article>
    </div>

    <div class="plugin-install">
      <div>
        <span class="plugin-install-label">INSTALL A MODULE</span>
        <strong>One command. Explicit state change.</strong>
        <p>The payload is copied into the workspace, its version is pinned, and supported runtime marketplaces are refreshed.</p>
      </div>
      <div class="command-card">
        <span class="command-title">workspace</span>
