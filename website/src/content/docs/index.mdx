  <section class="landing-capabilities" aria-labelledby="capabilities-title">
    <div class="section-heading">
      <div class="section-kicker">02 / WHAT LASSO OWNS</div>
      <h2 id="capabilities-title">Make the workspace legible.</h2>
      <p>Keep the coordination layer small, explicit, and durable. Let the agent runtime and each project do the work they already own.</p>
    </div>

    <div class="capability-list">
      <article class="capability-row">
        <span class="capability-index">01</span>
        <div>
          <h3>Project registry</h3>
          <p>Identity-only TOML entries make every repository discoverable without copying its toolchain into the workspace.</p>
        </div>
        <code>project-defs/*.toml</code>
        <span class="capability-arrow" aria-hidden="true">↗</span>
      </article>
      <article class="capability-row">
        <span class="capability-index">02</span>
        <div>
          <h3>Stable checkouts</h3>
          <p>Bootstrap ordinary clones and create task worktrees with predictable paths, so agents can move with confidence.</p>
        </div>
        <code>lasso setup</code>
        <span class="capability-arrow" aria-hidden="true">↗</span>
      </article>
      <article class="capability-row">
        <span class="capability-index">03</span>
        <div>
          <h3>Installable skills</h3>
          <p>Package judgment-heavy workflows as modules that follow the Codex baseline and adapt cleanly to other runtimes.</p>
        </div>
        <code>lasso module add</code>
        <span class="capability-arrow" aria-hidden="true">↗</span>
      </article>
      <article class="capability-row">
        <span class="capability-index">04</span>
        <div>
          <h3>Durable handoffs</h3>
          <p>Keep cross-session coordination in work items while live goals, plans, and task state stay with the agent runtime.</p>
        </div>
        <code>work-items/</code>
        <span class="capability-arrow" aria-hidden="true">↗</span>
      </article>
    </div>
  </section>

  <section class="landing-principles" aria-labelledby="principles-title">
    <div class="section-heading section-heading--compact">
      <div class="section-kicker">04 / THE CONTRACT</div>
      <h2 id="principles-title">Thin by design.</h2>
      <p>Lasso is useful because it knows where to stop.</p>
    </div>
    <div class="principle-grid">
      <article class="principle-card">
        <span>01</span>
        <h3>Agent-first</h3>
        <p>Codex remains the execution kernel; Lasso supplies the workspace context around it.</p>
      </article>
      <article class="principle-card">
        <span>02</span>
        <h3>Project-owned</h3>
        <p>Builds, tests, deploys, secrets, and runtime state stay with the owning project.</p>
      </article>
      <article class="principle-card">
        <span>03</span>
        <h3>Composable</h3>
        <p>Optional modules evolve independently and stay pinned in the workspace lockfile.</p>
      </article>
    </div>
